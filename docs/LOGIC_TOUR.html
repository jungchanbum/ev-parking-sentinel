1판독 재료 — 크롭 2경로

앱은 번호판 이미지를 두 경로로 얻는다. WiseAI가 잘라주는 good-shot(ImageRef)과, 앱이 풀해상 스냅샷에서 라이브 bbox로 직접 자르는 버스트. 카메라 센서가 거울상이라 두 경로 모두 판독 직전 좌우 반전 보정(kFlipCropH)을 거친다.

베스트 프레임 모드 (best_frame_mode=1, 옵션): 진입~주차 동안 버스트 크롭을 OCR하지 않고 sharp×√면적 점수만 매겨 챔피언 1장을 보관, 주차 확정 순간 그 1장만 정독한다. 채널당 1대 전제의 저부하 모드 — 여러 대 동시 인식엔 0(투표 모드)으로 둘 것.

2OCR 엔진 내부 — 한 장을 읽는 법

Recognize() 한 함수가 파이프라인 전체다. 핵심 헌법: "선택 이후 conf를 올리는 모든 가공은 0.94 캡" — 가공본이 오답을 게이트(0.95) 위로 부스트한 사고가 4번 반복된 뒤 세운 규칙.

  • 문법 검사: 숫자 2~3 + 한글 1 + 숫자 4 (지역판은 한글2 접두). 무효 텍스트는 어느 관문에도 못 들어간다.
  • 신뢰도 = CTC 비블랭크 스텝 확률의 기하평균. 로그의 conf가 이 값.

33단 판정 — 오확정 0의 구조

오독은 반드시 나온다는 전제로, 오독이 ★FINAL까지 살아나가지 못하게 관문을 겹겹이 세웠다.

명부(registered_plates.txt)의 역할은 번호 교정뿐이다. EV 여부의 출처가 아니다 — EV는 모든 차가 실조회(§5). 실전의 "아파트 등록차 목록"에 해당하는 정당한 화이트리스트 레이어.

4주차 판정 상태기계

구역(4점 폴리곤)은 웹 UI 클릭 4번 또는 /parking_roi로 등록하고 카메라에 영속화된다. 판정은 채널별로 아래 상태기계가 돈다.

  • 점유 유지: 칸을 덮는 "정지" 차가 보이면 WiseAI id가 바뀌어도 점유 유지 (id 뺑뺑이 흡수).
  • 판독 게이트 NeedsRead: 읽을 일(번호/EV 미확정 칸)이 있을 때만 OCR 가동. 전 칸 완결이면 채널 침묵.
  • 위반 = 점유 ∧ 비EV. EV 미확정(unknown)은 위반으로 치지 않는다 — 억울한 알람 방지.

6외부 연동 — notify-then-fetch

이벤트 채널(EventStatus)은 펌웨어 제약으로 불리언만 실을 수 있다. 그래서 2채널로 나눴고, 클라이언트 규칙은 3줄이면 끝난다: "Occupied 라인이 오면 (값 무관) XML을 읽고 violation 필드로 판단하라."

7실측으로 확정한 교훈들

① 모형 판은 폰트가 전부다 근본 원인 둥근 범용 폰트 인쇄물은 sharp 2000+로 선명해도 체계 오독(9→0, 서→거). 실판 글리프는 강블러·저해상·원근에도 정독. 같은 판에서 conf 0.80→1.00. 초점·크롭·후처리를 의심하기 전에 폰트부터.
② 센서 거울상 — 스냅샷의 로고를 봐라 판독 전량 헛것이면 원본 스냅샷에서 차 로고 방향부터 확인. 로고가 뒤집혀 있으면 센서가 거울상 — kFlipCropH=true. 거울상 크롭은 항상 완전 헛것("89?8184"류)을 뱉는다.
③ 가공 판독은 0.94 캡 지터·조도·디블러 등 가공본이 오답을 게이트 위로 부스트한 사고 4회 반복. 원본 판독만 단독으로 게이트를 넘을 자격이 있다.
④ 필터 문턱은 실측 분포에서 크롭 sharp 하한 600은 실크롭(≈488)까지 죽여 전량 starving. 쓰레기(≈300)와 실크롭 사이인 150이 정답 — 분포를 재보고 문턱을 놓을 것.
⑤ 매니페스트는 app/src가 원본 빌드가 app/src → app/bin으로 재생성. 포트 등 수정은 반드시 app/src에. 디버거 뷰어는 앱 SkeletonPortNumber 고정(8590) + 뷰어 설정 일치로 연결.
⑥ 앱 내 TLS 금지 · 설치 수칙 앱 프로세스에서 OpenSSL TLS = 즉사 → 외부 HTTPS는 popen curl 자식. cap 설치는 영상 정지 + 물리 재부팅 직후 — 연속 설치는 반쯤-설치 오염.
